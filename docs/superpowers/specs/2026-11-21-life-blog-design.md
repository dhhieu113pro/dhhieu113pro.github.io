# Life blog — design

## Intent

A public blog at `dhhieu113pro.github.io` (repo `dhhieu113pro/dhhieu113pro.github.io`, description "Termux.io.vn", Pages enabled on `main`). Posts come from `pwterm story <url>`, which crawls an article, rewrites it to Vietnamese, generates one illustration per part, and stores the result in `~/.pwterm/stories/stories.sqlite`. The blog turns those records into live, readable posts.

## Goals

- Home page listing all stories, newest first, with title, date, byline, cover image, and link.
- One page per story: title, byline, source link, date, and the story's `parts` in order — each part's text plus its generated image.
- Repeatable publish flow: run one script, commit, push, live.
- Mobile-first, readable typography, accessible markup, no runtime dependencies.

## Non-goals / anti-goals

- No CMS, comments, accounts, search backend, or build framework.
- No client-side data fetching from a server — GitHub Pages is static.
- Do not modify pwterm; the blog is a separate repo that reads pwterm's data.

## Constraints

- Termux phone: Node 26 and Python 3 available; `node:sqlite` is built in, so no npm install needed.
- Images generated by pwterm are `.webp` files in `~/.pwterm/stories/<slug>/<n>.webp`.
- Story records are JSON in the `record` column; schema is `slug`, `record`, `created_at`.
- gh CLI is authenticated as `dhhieu113pro` with `repo` scope; push over HTTPS works.
- Published URLs are under `https://dhhieu113pro.github.io/` (user site, repo root).

## Approaches

- **A (chosen): static HTML + sync script.** `scripts/sync.js` reads the SQLite DB, copies images into `assets/img/<slug>/`, writes `posts/<slug>/index.html`, and rebuilds `index.html`. Simple, offline, no deps. Cost: publishing is an explicit command + commit + push.
- B: blog loads a generated `posts.json` at runtime. Same export step plus JS rendering and weaker SEO — rejected.
- C: pwterm writes HTML into the blog repo. Couples two projects — rejected.

## Decisions

- UI language: Vietnamese labels (matches the rewritten posts). Site name `Termux.io.vn`.
- Layout: single-column reading view, max-width ~720px; home lists stories as cards with cover image.
- Styling: one plain `assets/style.css`. No external fonts/CDNs — fully offline-friendly.
- All HTML generated by the sync script; source of truth stays the pwterm DB.
- Slugs come from pwterm and are validated (`^[a-z0-9]+(-[a-z0-9]+)*$`) before files are written.

## What's left to the builder

- Choose the exact HTML/Tailwind-free CSS look; the user approved the approach, not the pixels.
- Seed with the two existing stories during the first sync.
- Verify rendered pages locally before pushing; confirm Pages serves them after push.
