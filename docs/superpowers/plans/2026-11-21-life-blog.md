# Life Blog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a static Vietnamese story blog at `dhhieu113pro.github.io` whose posts are generated from pwterm's story database by a single dependency-free script.

**Architecture:** `scripts/sync.js` is the only writer of HTML and images. It reads pwterm's SQLite stories table, copies each story's illustrations, writes one HTML page per story under `posts/<slug>/`, and rebuilds the home listing. GitHub Pages serves the committed files; no runtime code.

**Tech Stack:** Node 26 built-ins only (`node:sqlite`, `fs`, `path`), plain HTML/CSS, Node's built-in test runner, gh CLI for push.

**Spec:** `docs/superpowers/specs/2026-11-21-life-blog-design.md`

## Global Constraints

- No npm dependencies, no build framework, no client-side fetching.
- Node `>=22.5` for `node:sqlite` (phone has Node 26).
- Story slugs must match `^[a-z0-9]+(-[a-z0-9]+)*$` before any file path is built.
- All story-derived text inserted into HTML must be escaped; story `source` must be escaped as an attribute.
- UI labels in Vietnamese; every page declares `<html lang="vi">` and UTF-8.
- Output site is the repo root (user Pages site), so links are relative and work at `/`.
- `posts/` and `assets/img/` are generated directories; the sync script may replace them wholesale.

## Review Focus

- A story title/byline/part containing `<`, `&`, or quotes must render as text, not markup — `scripts/sync.test.js` asserts escaped output for a title with `<script>` and a part with `&`.
- A slug with `../` or uppercase must be rejected before filesystem writes — test passes an invalid slug fixture and asserts no file is created outside `posts/`.
- A missing image file for a part must not crash the sync — test fixture omits one image and asserts the page is still written with no broken `<img>` for it.
- An empty stories database must produce a valid home page with an empty-state message — test with an empty fixture DB.
- Multiple stories must be listed newest first by `created_at` — test with two fixture records and assert ordering in `index.html`.

### Task 1: Sync script with tests

**Files:**
- Create: `scripts/sync.js`
- Create: `scripts/sync.test.js`
- Create: `scripts/fixtures/make-db.js`

**Interfaces:**
- Consumes: pwterm DB at `~/.pwterm/stories/stories.sqlite`, table `stories(slug, record, created_at)`; `record` is JSON with `title`, `byline`, `source`, `createdAt`, `parts[{kind,text,image}]`; images at `~/.pwterm/stories/<slug>/<image>`.
- Produces: `node scripts/sync.js [--db <path>] [--out <dir>]` — copies images to `assets/img/<slug>/`, writes `posts/<slug>/index.html`, writes `index.html`, prints a one-line summary. Exports `syncStories({dbPath, outDir})` for tests.

- [ ] **Step 1: Write fixture helper**

`scripts/fixtures/make-db.js` exports `makeFixture({dir, stories})` that creates a `stories.sqlite` with the real schema, inserts each story (JSON-stringified `record`), and creates `<dir>/stories/<slug>/<image>` files for each part unless `story.skipImage` is set. Returns the db path.

- [ ] **Step 2: Write failing tests**

`scripts/sync.test.js` uses `node:test` and `node:assert`. Each test calls `makeFixture` into a temp dir and `syncStories({dbPath, outDir})`, then asserts:
1. escaping: title `<script>x</script>` and part text `a & b` appear escaped in the post HTML;
2. slug rejection: record slug `../bad` is skipped and no file is created above `outDir`;
3. missing image: `skipImage` story still produces a post with no `<img>` for the missing file;
4. empty DB: `index.html` exists and contains the Vietnamese empty-state line;
5. ordering: two stories with `createdAt` a day apart list the newer one first in `index.html`.

- [ ] **Step 3: Run tests to verify they fail**

Run: `node --test scripts/sync.test.js`
Expected: FAIL (module `sync.js` missing).

- [ ] **Step 4: Implement `scripts/sync.js`**

`syncStories({dbPath = default, outDir = repo root})`: open DB read-only, select rows ordered by `created_at DESC`, parse JSON, skip invalid slugs, escape all text, copy existing images with `fs.copyFileSync`, write post pages with each part's text and image in `parts` order, delete and recreate `posts/` and `assets/img/` before writing, rebuild `index.html` with cover image (first part's image), title, byline, date (`toLocaleDateString('vi-VN')`), and relative links. CLI arguments override the two defaults. Print the story count.

- [ ] **Step 5: Run tests to verify they pass**

Run: `node --test scripts/sync.test.js`
Expected: PASS (5 tests).

- [ ] **Step 6: Commit**

```bash
git add scripts/
git commit -m "feat: pwterm story sync script"
```
